# Phase 3 pinned cross-device transfer probe

The `gpu_4070_transfer` CTest is opt-in to the machine-targeted build and runs with `CUDA_VISIBLE_DEVICES=1,0`. It initializes the 5060 Ti CUDA context first, allocates 1 MiB of portable/mapped pinned host input and output, then initializes the 4070 SUPER context. On a device-1 nonblocking stream it copies H2D, runs a byte-transform kernel, copies D2H, records an event and waits for it before checking every output byte. It also queries CUDA/NVML free memory on the PCI-matched display GPU and requires the conservative 2560 MiB floor. All device and pinned allocations belong to this test process. A direct run passed and reported 9.597 GiB lower free; adjacent `nvidia-smi` read 9,991 MiB free before and after.

This falsifies the concern that **two CUDA contexts alone** or a small portable pinned handoff cannot work on this machine. It does not solve the large ~29 GiB `cudaHostRegisterPortable` expert arena interaction seen during the full model run. It does not exercise Q2_0 kernel grouping, expert partial rows or overlap with CPU work. The separate optional `gpu_4070_q2_parity_layer0/layer47` CTests cover Q2_0 kernel arithmetic directly on the 4070; the next test must combine these properties at the real verify-window seam.

## Combined two-context Q2_0 parity

The native Q2_0 parity executable now accepts `--secondary` as its final argument. It keeps a CUDA context on the 5060 Ti, places two real model blobs into verified `SecondaryArena` slots on the 4070 SUPER, and runs the existing native grouped kernel there for three entries across two expert groups. Optional CTests `gpu_dual_q2_parity_layer0` and `gpu_dual_q2_parity_layer47` run with `CUDA_VISIBLE_DEVICES=1,0`; both passed. Layer 0's boundary seed and layer 47's normal seed each reported 0/7,680 differing output floats versus the CPU pool. A direct layer-0 run reported 9.595 GiB lower free during the test. An initial test version reached an illegal memory access in its extra gate diagnostic because that diagnostic still used the now-null legacy `dblob` pointer; switching it to the verified secondary slot fixed the harness. The grouped output had already matched before that diagnostic. This validates staging plus kernel arithmetic with both contexts alive, but the test still uses an ordinary host activation copy; the separate pinned-transfer test validates portable pinned H2D/event/D2H. The model's verify-window routing and merge remain unimplemented.
