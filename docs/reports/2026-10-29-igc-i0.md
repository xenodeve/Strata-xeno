# IGC I0: native head fidelity and a declared late-head gradient

Tracking: [#276](https://github.com/xenodeve/Strata-xeno/issues/276).
This is an implementation checkpoint, not completion of the IGC PRD or a trained
latent capability. IGC is primary; compiled Qwenputer remains a comparator.

## What was established

The isolated main-based candidate captured a nonzero final HC residual and head
input from real Gyro-M inference. Replaying that residual through the existing
fused HC mixer and native Q8 head reproduced **all 248,320 logits bit for bit**:
`bitwise_differences=0 max_abs=0 argmax=15968 expected_argmax=15968`.
Direct replay of the captured 2,560-value head input is tested separately.

The optional `igc_head_probe` uses the engine's existing frozen weights and
forward kernels. It neither executes an arithmetic program nor injects an adapter
into generation. Its zero control, nonzero independent Q8-block oracle, wrong-logit
negative control, malformed input checks, repeat check, and sparse-gradient oracle
are distinct from learned-model quality evaluation.

`head_vjp.cu` computes `W_dequant.T @ delta` for the frozen Q8_0 head. The offline
PyTorch bridge uses **an explicit straight-through estimator across Q8_1 activation
quantization**. It is not the exact derivative of that quantizer. This late
head-input variant avoids backward through Gyro's GDN/MoE/attention suffix; it is
not a reproduction of the paper's early-layer output mapper.

On one captured input, one bounded gradient step reduced native-forward cross
entropy from **17.0878792 to 16.9868813**. Target token ID 391 is an arbitrary
diagnostic class, not an arithmetic answer. The original activation and base
weights were not updated. There is no trained result mapper, operand mapper or
readiness trigger yet. The process-per-call bridge is a feasibility tool, not the
production path or evidence of low latency.

## Why the existing capture initially failed

The deployed daily executable generated token 15968 and nonzero first-window
logits, but its existing `--dump-residual` and `--dump-mixed` read session-loop
buffers that the native verifier did not use. Both dumps were zero. Replaying
that residual disagreed with **248,320/248,320 logits**, maximum absolute error
20.1713696. This is the red reproducer, not usable training data.

The correction adds `Verifier::copy_head_input`, selects the last accepted input
row, copies the actual verifier residual/head input on its explicit stream, and
fences before returning. Only existing opt-in CLI dump flags call it. The ordinary
generation path has no copies, new activation cache or adapter. The native flags
now retain the intended dump semantics instead of publishing stale session data.
The non-verifier token loop retains its existing dump path.

The corrected capture came from the isolated **main-based candidate**, not the
deployed daily executable. Their first-logit files have different hashes; no
daily-versus-main bitwise parity is claimed. The fidelity check compares capture
and replay from the same candidate execution and same model/pack inputs.

## Actual Hub configuration and resources

The selected profile is Gyro-M 262K, 5 workers, unchanged context/RoPE, KV, MTP,
suffix, expert tiers and cache settings. Its actual arguments already include
pool/process priority 2. Those priorities were not added by this harness.
The diagnostic uses CLI mode and a short prompt, not a served long-prefix latency
benchmark. Task-owned expert-profile copies, passive memory polling, an emergency
timeout and kill-on-close cleanup are disclosed differences.

The former **26 GiB** physical admission threshold came from the diagnostic
harness. The selected Hub `:gyrom` route actually sets `NEEDGB=24`; capacity mode
sets 26. The first I0 attempt was refused without starting a model. The corrected
harness follows the selected **24 GiB** Hub check; an additional disclosed
system-commit safety estimate and emergency floors do not alter model behavior.
No private-commit cap, pagefile/security change or unrelated process termination
was introduced.

## Remaining I0 and subsequent work

Before treating the late-head variant as a viable result mapper, measure a bounded
conditional adapter on held-out result/context pairs, including final-answer
faithfulness and repeated uses. This one-step loss result establishes a usable
surrogate signal, not generalization. The paper-style early-layer route still
lacks a demonstrated differentiable frozen suffix in this engine.

Input/readiness training needs real captured states with model, tokenizer,
pack/build/config, prefix, position, layer and dtype identity. Full 262K HC caches
would take 5 GiB BF16 or 10 GiB F32 by shape calculation; bounded selected/projected
state capture and actual resource measurements precede larger training.
Typed exact execution, learned operand extraction, result mapping, repeated
committed triggers and practical end-to-end evaluation remain separate gates.

Primary research: [IGC v1](https://arxiv.org/html/2501.00684v1). No official runnable
code/checkpoint or software license was established; this diagnostic was written
independently using the existing Strata engine and installed tools.

## Scope review of the checkpoint

The native-head test target is opt-in and not linked into the default executable.
The verifier change only reads state when an existing dump flag is selected;
`copy_head_input` rejects rows outside the completed window and delegates to the
head-owning stage. It does not advance positions, cache state or sampling. The
probe validates finite vectors/geometry before GPU work; mismatched evidence is
refused rather than accepted from its argmax alone. The VJP writes only its output,
uses fixed ordered shared-memory reduction and never updates frozen weights.
The Python feasibility bridge is CPU-only autograd and validates shape/dtype and
finite inputs before spawning a bounded, no-window native process.

Manual review is not an independent full-branch review or an exemption from the
remaining backend, model-quality, ownership and rollout gates. No PR is opened.
