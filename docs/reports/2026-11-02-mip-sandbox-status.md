# MIP + Sandbox: สถานะการพัฒนา

ณ 2026-11-02 branch `xeno/mip-sandbox` (เดิม `xeno/native-qwenputer-p0`) ตัวเลขทั้งหมดมาจาก A100 80GB เครื่องเดียว greedy และ LiveCodeBench hard 10 ข้อที่คัดไว้ ตรวจด้วย test ของ benchmark เอง ส่วนวิเคราะห์เชิงลึกอยู่ใน `docs/reports/2026-11-02-mip-sandbox-effectiveness.md`

## สรุป

**ส่วนประกอบสร้างครบเกือบทั้งหมดแล้ว แต่ยังไม่พร้อมเปิดใช้ในงานจริง**

- **ข้อง่าย ลด token ได้จริง** ข้อที่ทั้งแขนฐานและแขนใหม่ทำถูก ใช้ token ราวครึ่งหนึ่งของแขนไม่มี MIP
- **ข้อยาก ยังพิสูจน์ไม่ได้** ยังไม่มีข้อไหนที่โมเดลเห็นผลทดลองผิด แล้วแก้สมมติฐานจนถูก ชุด 10 ข้อนี้มีข้อที่แขนฐานผิดด้วยเหตุจริงแค่ข้อเดียว
- **ผลที่มีแนวโน้มดีที่สุด:** ให้โมเดลเรียก tool `run_python` ในรูปแบบที่ถูก train มา แล้วมันทดลองเอง ทั้งรันตัวอย่าง, เขียน brute force มาเทียบบน input สุ่ม และวัดเวลากับ input ใหญ่ โดยไม่มีกฎบังคับ

## ผลที่วัดได้

| แขน | กลไก | ถูก (จาก 10) | Token รวม | Token บนข้อที่ถูกทั้งคู่ เทียบไม่มี MIP |
|---|---|---:|---:|---|
| `lon` | ไม่มี MIP | 7 | 497,237 | 1.00 |
| `lop` | MIP ไม่มี Sandbox | 8 | 157,111 | |
| `ld1` | รันร่างทันที, ด่านก่อนจบ | 9 | 247,755 | |
| `ld2` | `ld1` + ปิดเมื่อ test ผ่าน | 8 | 207,797 | 1.05 (0.47 ถ้าไม่นับ 3781) |
| `lt1` | โมเดลเรียก tool เอง | 7 | 174,579 | **0.51** |

อ่านตารางนี้ต้องรู้ 4 เรื่อง

1. ข้อ 3344 ตัดสินด้วย test ซ่อนที่ผิดรูปในข้อมูลของ benchmark เอง (input `[0, 0]`) เลข 9 ของ `ld1` จึงสูงเกินจริงไป 1
2. ข้อ 3781 ในแขนที่ปิดกฎ "ปิดเมื่อค่าซ้ำ" วนจนใช้ 113,756 token เทียบ 59,960 ของ `lon` เลข 1.05 ของ `ld2` มาจากข้อนี้ข้อเดียว ส่วน `lt1` ใช้ 27,949
3. `lt1` เสีย 3674 และ 3478 เพราะ bug ของ bench ไม่ใช่ของโมเดล โมเดลเรียก tool ระหว่างที่ยังคิดอยู่ ตัวอ่านรับเฉพาะในคำตอบ พอไม่มีผลกลับ โมเดลจึงแต่งผลขึ้นเองแล้วจบโดยไม่มีโค้ด แก้แล้ว และ `lt2` กำลังรันซ้ำ
4. ตัวชี้วัดหลัก "เห็นผลผิดจริง แล้วแก้จนผ่าน" เป็น 0 ทุกแขน

## สถานะแต่ละส่วน

| ส่วน | ทำอะไร | สถานะ | หลักฐาน | ที่ยังขาด |
|---|---|---|---|---|
| MIP Native: ค่าจากการคำนวณ | ใส่ค่าที่ถูกต้องหลัง `A op B =` ระหว่างคิด | วัดกับโมเดลแล้ว | `lop` ถูก 18 ต่อ 17 จาก 20 ข้อ, token 0.40 เท่า | ตัวแปรและฟังก์ชัน เอื้อมถึงเพิ่มได้ราว 11 % |
| MIP Native: กฎหยุดการวน | ปิดการคิดที่วนไม่จบ | วัดกับโมเดลแล้ว | 3460 จากไม่มีโค้ด (261,415 token) เป็นถูก | |
| Sandbox: ตัวแปลภาษาของเรา | รันโค้ดในการคิดโดยไม่ต้องมี Python | ใช้ในทุกแขน | 577 โปรแกรมตรงกับ CPython | |
| Sandbox: Python จริงในกล่อง | sympy, numpy, random ใน kernel ที่จำชื่อข้าม block | ใช้บน A100 แล้ว | ผ่าน test บนเครื่องนี้ 7 ข้อ | **D1: รอผู้พัฒนาอนุญาตให้รันบนเครื่องนี้** |
| กำแพง isolation | AppContainer + Job Object | ผ่าน test | escape test 101 ข้อ | disk limit เป็นการตรวจเป็นระยะ, โค้ดในกล่องรู้ว่า path ใดมีอยู่ |
| Workspace, ตัวค้น, symbol | สำเนา project, ค้นแบบ Serena | ผ่าน test | 177 test | tree-sitter ยังไม่เคยรัน, ยังไม่รันบน Linux |
| เส้นทาง tool ของ Sandbox | `sandbox_run/read/grep/edit/test/diff/apply`, conflict, นำขึ้นของจริง | ผ่าน test | 160 test ใช้กล่องจริง | ยังไม่รันในแชตจริง |
| MIP Adapter | เรียก MCP server จาก block ในการคิด (Roadmap M1, M2) | ผ่าน test | 80 test, kernel บน A100 ใช้ได้ | ยังไม่มีโมเดลจริงเรียก, ไม่มีสถานะบนหน้าเว็บ, M3-M5 ยังไม่สร้าง |
| กฎ: รันร่างทันที, ด่านก่อนจบ, ปิดเมื่อผ่าน | ทดสอบร่างตอนที่มันเสร็จ | วัดกับโมเดลแล้ว | `ld1`, `ld2` | ยังไม่มีข้อที่แก้สมมติฐานสำเร็จ |
| กฎ: brute force จากโจทย์ | oracle สำหรับข้อที่คิดยาว | แก้แล้ว รอรัน | `lb1` เสีย 2952 จึงหยุดตั้งแต่ข้อแรก | `lb1b` ในคิว |
| กฎ: ตรวจด้วยโปรแกรมแทนมือ | ต่อ `Let's verify` เป็นโปรแกรม | สร้างแล้ว รอรัน | | `ac4` ในคิว |
| Tool loop ในรูปแบบของโมเดล | โมเดลเรียก `run_python` เอง | วัดแล้ว 1 แขน | `lt1` | `lt2` กำลังรัน, ตอนนี้อยู่ใน bench ยังไม่อยู่ใน server |
| ระบบทดสอบ | ใช้ผลเดิมเมื่อกฎเปลี่ยนไม่ได้, ข้อสั้นก่อน, หยุดเมื่อเสียข้อ, PC คัดข้อ | ใช้งานแล้ว | `lb1` หยุดที่ข้อแรกตามที่ออกแบบ | |

## ใกล้ใช้งานจริงแค่ไหน

"ใช้งานจริง" ในที่นี้คือ เปิดใน server โปรไฟล์ D2x ให้ Claude Code ใช้ แล้วได้ผลดีกว่าไม่เปิด ทั้งความถูกต้องและ latency ตามเป้าหมายใน `AGENTS.md`

| ขั้น | งาน | ขึ้นกับ |
|---|---|---|
| 1 | เลือกเส้นทางหลักจาก `lt2` และ `lb1b` | ผลจาก A100 ภายในไม่กี่ชั่วโมง |
| 2 | ถ้าเลือกทาง tool: ย้ายการรับ tool call ระหว่างคิดจาก bench เข้า server และ engine ให้ผลกลับเข้าการคิดโดยไม่ต้องจบ turn | งานพัฒนา |
| 3 | อนุญาต D1 ให้รัน Python จริงบนเครื่องนี้ | ผู้พัฒนา |
| 4 | สถานะของ Adapter และ Sandbox บนหน้าเว็บ และต่อสายตอน server เริ่ม | งานพัฒนา |
| 5 | ทดสอบในแชตจริงบน PC โปรไฟล์ D2x และวัด latency ต่อ turn | ขั้น 2-4 |
| 6 | ทดสอบเต็มเทียบคะแนนที่ Base เผยแพร่ ไล่จากชุดเล็กไปใหญ่ | ราว 12-20 ชั่วโมงของ A100 |
| 7 | ใส่ใน config ที่ใช้จริง | ผู้พัฒนา เพราะ config เป็นของผู้พัฒนา |

## ความเสี่ยงที่รู้อยู่

- **ตัวอย่างน้อย:** 10 ข้อ รอบเดียว เครื่องเดียว ทุกผลต้องยืนยันบนชุดใหม่ก่อนสรุป PC กำลังคัดข้อ LiveCodeBench hard เพิ่มอีก 30 ข้อเพื่อหาข้อที่แขนฐานผิด
- **งบ:** เหลือ 196 compute units หรือ A100 ราว 22 ชั่วโมง ขณะที่งานที่วางไว้อาจใช้มากกว่านั้น A100 เครื่องที่สองถูกปฏิเสธ
- **ข้อยากยังไม่มีหลักฐาน:** ผล HLE แบบไม่มี MIP ยังไม่ได้รัน
- **การวนในแขนที่ไม่ปิดเมื่อค่าซ้ำ:** 3781 ยาวขึ้นเกือบ 2 เท่า
