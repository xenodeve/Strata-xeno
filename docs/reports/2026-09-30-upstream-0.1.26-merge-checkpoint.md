# Upstream 0.1.26 merged with Strata-xeno: what the merge did to each earlier optimisation (checkpoint)

**Date:** 2026-09-30. **Issue:** #45 (parents #43, #30). **Status:** an experiment. The merged engine lives on the local
branch `xeno/exp-upstream-0.1.26-dyn` (`C:\Strata-exp\src-dyn`, merge `6c09c5b`, probes `7b31aa6`), which is not pushed
and is not the daily server. This report is the checkpoint: which of this branch's optimisations survived the merge,
which upstream replaced, and what changed in speed, RAM and output.

**Sources.** Every issue of this repository (#1-#45, bodies and comments, open and closed) was read and compared with
the merged source. The numbers come from #45's two result comments and the run logs in `C:\Strata-exp` (`m1`-`m9`).
**MEASURED** means a same-session run in both orders at HIGH class, unless the line says otherwise. **UNMEASURED** marks
an estimate. A number with no tag is not supported.

Arms: **U** upstream 0.1.26 as its `setup.py` configures this PC, **O** Strata-xeno `7134ce9`, **D** the merged engine.
**1** one card (5060 Ti), **2** the dual config (5060 primary + 4070 expert tier), **w** split + wave.

---

## 1. The merge

`6c09c5b` merges `xeno/claude-merge-0.1.20` into upstream v0.1.26: 14 conflicted files, ~74 hunks. Its rules (commit
message):

- **Where both sides built the same optimisation, ours is kept**, because the rest of our code depends on it and it was
  proven byte-identical: the stager ring's jobs, the MMQ sub-bounds, the issuer, the 4070 dispatch, H2 merge of
  partials, lent-slot refill from the tail file. The issuer is now **on by default**, as upstream's D-5 is.
- **Upstream-only features are taken:** layer split (stage ranges, hand-off, remote experts), C-2 batched indexer
  append, C-4 embedding gather, the combine of a window's rows in one launch, prefill phase timers, `max_pinned_bytes`.
- **Dropped:** upstream's PCIe probe. On the 5060 Ti's x4 link it turns the read path on, which #27 measured at
  3.24 tok/s.
- **Our #42 ports** of upstream `fe609ce` / `882bb6d` / `b046845` are removed; upstream's own copies stay.

Our Python tests pass on the merged tree (93, #45).

## 4. What got worse or is new

1. **Exit hang in generate mode.** The Stager's four threads return, but the first `join` never does
   (`STRATA_EXIT_TRACE`). The runs end with `STRATA_EXP_QUICK_EXIT=1`, which is a bypass, not a fix. Serve is not
   affected. Root cause unknown.
2. **Outputs differ from O.** D gives `60f0e5af` / `5b5884bc` against O's `050eee61` / `e7211023`, because of upstream's
   numerics (for example the one-launch window combine). A quality gate is needed before D's outputs are trusted.
3. **Non-determinism:** the merged layer split (D3u: `75592447` / `f0b1a8da`) and upstream's thai (three hashes in U1).
   The dual config and one card are deterministic on D.
4. **Upstream's layer split costs RAM on D:** D3u has a 24.2 GiB working set and 47.1 GiB commit, against D2's 16.5 /
   39.1, and its code decode is lower (78-79 vs 83-89 tok/s).

## 5. Correction: the split + wave arms ran with a 2.27 GiB 4070 tier

The `D2bw` / `O2bw` rows use #35's reproduce line, which passes `--expert-profile D:\Github\Strata\data\expert-profile.bin`.
That profile holds **8,000 pairs**. The 5060 takes 6,239, so only **1,761** remain for the 4070
(`secondary_candidates`, `generate.cpp:2996`), whatever `--secondary-expert-mib` asks for. The log says so:
"staged 1761 next-ranked secondary experts (2.27 GiB)" (`m5-8k-3-D2bw.stderr`; O2b and O2bw show the same).

| arm | profile | 4070 tier | host-owned experts | working set at 8K |
|---|---|---|---|---|
| D2bw / O2bw (`m5`) | 8,000 pairs | 1,761 / 2.27 GiB | 21.34 GiB | 23.1 GiB |
| D2w / O2w (`m4`) | ranked, 24,576 pairs | 4,854 / 6.25 GiB | 17.36 GiB | 18.8 GiB |
| D2 decode (`m9`) | ranked, tier 8704 | 6,602 / 8.50 GiB | 15.11 GiB | 16.4 GiB |

So the 1,925 tok/s prompt figure has no decode or RAM figure at the intended tier. It must be re-measured with the ranked
profile before it supports a daily config. The daily one-card args use the same 8,000-pair profile, which is harmless
with no tier, but a dual daily config needs the ranked one.

## 6. RAM: where it goes and what is left

MEASURED on the three rows above: **working set ≈ host-owned experts + 1.3-1.8 GiB.** Every GiB of experts a GPU tier
holds is a GiB of RAM. Private commit stays at about 37-40 GiB because WDDM charges VRAM allocations to commit (#4); it is
not resident RAM.

What can still lower RAM on the merged engine, largest first (details in #45, comment of 2026-09-30):

| lever | RAM | cost | state |
|---|---|---|---|
| ranked profile on the split + wave arm | about −4.0 GiB at 8K (UNMEASURED; D2w measured 18.8 vs 23.1) | none known | a flag change |
| S4c: borrow the 4070 tier during a prompt, refill from a 4070 tail file (#39) | −2.25 GiB (UNMEASURED) and decode +5 % (#36 reversed) | ~2 GB disk, ~0.46 s refill per fresh long prompt (simulated) | not built |
| lower the 5060's `--vram-reserve-mib` from 2400 now that the prompt path borrows | up to −1.6 GiB (UNMEASURED) | #10 saw a hang at 2000 with own buffers | needs a probe |
| Dm frontier as the split path's default (#41) | about −0.7 GiB (703 MiB of 4070 VRAM MEASURED; RAM estimated) | a hard error if a layer exceeds the pool | parked for the developer |
| `--ram-cache-gib` 12 / 10 / 8 (#11) | −2.6 / −4.6 / −6.6 GiB (MEASURED on O) | decode −21 / −33 / −41 % | opt-in |

No further RAM comes from porting: every Strata-xeno memory mechanism is already in the merged engine (§3.1).
