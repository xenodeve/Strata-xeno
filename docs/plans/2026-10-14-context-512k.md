# Plan 2026-10-14: the served Gyro-M profile at 512K context

**Developer's decision (2026-10-14):** the served Gyro-M profile (hub key 3, `strata-gyro-m-d2x.json`) will extend
its context from the native 262,144 tokens to 524,288 with YaRN rope scaling, factor 2.

**Tracking issue:** xenodeve/Strata-xeno#232.

## What changes

- **Engine args:** `--max-context 262144` becomes `--max-context 524288 --rope-scaling yarn --rope-scale 2`. The
  engine and setup already support it (docs/DETAILS.md, "Context extension past 262K"). No code change is planned.
- **Client side:** DeepSeek Harness's `contextWindow` and its compaction `thresholdRatio` move with it. Today it states
  524,288 with ratio 0.3 so that `maxTokens: 256000` still compacts at ~157K.

## Why it is gated

| area | what is known | what is not |
|---|---|---|
| quality, short context | YaRN rescales the rotary angles at every position, so a scaled run is a slightly different model on every prompt; upstream saw no separation at 2.7K / 32K (IQ3_S) | Gyro-M |
| quality, past 262K | upstream: yarn 2 beats no scaling at 293K (NLL 2.04 vs 2.22); long-document Q&A 8/8 at 421K (IQ3_S, one machine) | Gyro-M |
| RAM | KV streaming keeps the whole KV cache in pinned RAM, ~13 KB per token with int8 KV, so the extra 262K is about +3.4 GB; private commit is 46.7 GiB at 262K today on a 48 GB PC | the measured figure |
| VRAM | `--kv-resident 65536` keeps 64K cells per layer on the card either way | the measured figure |
| decode past 262K | attention reads more KV, more of it from RAM | any figure |

**Fallback if the RAM does not fit:** `--kv k8v4`, which keeps V at rotated 4 bits and is 23 % smaller than int8 KV. At
512K that is about +2.6 GB instead of +3.4 GB. It is a trade-off of its own: the values are rounded to 4 bits.

## Gates (in order, each on a test config, never on hub key 3, with the server free)

1. **RAM:** private commit and RAM in use at boot and with a 450K prompt.
2. **Speed:** decode and prompt read at 4K / 128K / 300K / 450K against the current 262K config, ABBA.
3. **Short-context parity:** greedy outputs scaled vs unscaled on the same prompts, with the differences read.
4. **Long context:** a long-document question past 262K, answered correctly.
5. **The developer decides on the numbers.** The hub config and the harness settings then change together, with a
   backup and a `_comment` line as for every install.
