# แผน: ให้โมเดลรู้ว่าสมมติฐานผิดจากการทดลองใน Sandbox

สถานะ: อนุมัติโดยผู้พัฒนา 2026-11-02 ("เอาตามที่ research มาเลย") งานวิจัยและข้อมูลอยู่ใน `docs/plans/2026-11-02-sandbox-workspace-design.md` ส่วน 13

## เป้าหมาย

Sandbox และ MIP แทนการคิดทดของโมเดล เพื่อให้โมเดลตั้งสมมติฐานแล้วพิสูจน์ได้ระหว่างคิด ลำดับที่ต้องเกิดคือ ทดลอง, เห็นว่าไม่ตรง, เปลี่ยนวิธี, ลองใหม่

## เกณฑ์

1. ห้ามเสียข้อที่แขนฐานทำได้
2. จำนวนข้อที่ถูกเพิ่มขึ้น
3. ตัวชี้วัดหลัก: จำนวนข้อที่เห็นผลไม่ตรง แล้วเปลี่ยนวิธี แล้วจบที่คำตอบถูก
4. Token เพิ่มได้ถ้าแลกกับข้อ 2 ส่วนคำตอบถูกต่อ token ใช้เทียบเฉพาะแขนที่ไม่เสียข้อ

ทดสอบบน A100 เท่านั้น เพราะเครื่องนี้ให้ผลไม่ซ้ำ ทีละการเปลี่ยนแปลง เทียบกับแขนฐานบนข้อเดิม และอ่านทุกข้อที่เปลี่ยน ทั้งที่ได้และที่เสีย

**แขนฐานปัจจุบัน:** `lon` ไม่มี MIP 17 จาก 20, `lop` เปิด MIP ไม่มี Sandbox 18 จาก 20 (LiveCodeBench hard)

## ขั้นตอน

| ขั้น | งาน | ที่แก้ | ผ่านเมื่อ |
|---|---|---|---|
| H0 | วัดการเอากฎปิดเมื่อซ้ำและโน้ต `stop checking` ออก (`lfl` อยู่ในคิว) | ไม่ต้องแก้โค้ด | กู้ 3364 โดยไม่เสียข้ออื่น |
| H1 | ด่านก่อนจบ: แทนที่ `</think>` ครั้งแรกของ turn ด้วย hint ของ START แล้วเปิด block ให้ตรวจ | `igc_learned_diagnostic.hpp`, flag `--igc-sandbox-gate` | ไม่เสียข้อ และมีข้อที่แก้ตัวเองสำเร็จ |
| H2 | `check(ผลลัพธ์, ค่าที่คาด)` แทน `print(` โดยคาดค่าจากตัวอย่างในโจทย์ | prelude ใน `igc_sandbox_bridge.hpp`, flag `--igc-sandbox-check` | สัดส่วนการทดสอบกับตัวอย่างเพิ่ม |
| H3 | ผลไม่ตรงแล้วต่อด้วยบรรทัดให้โมเดลหาสาเหตุ | `igc_sandbox_bridge.hpp`, `igc_learned_diagnostic.hpp` | ข้อที่เห็นผลไม่ตรงจบถูกเพิ่มจาก 5 ใน 14 |
| H4 | ผลตรงแล้วให้ลองทางแย้ง: กรณีขอบ, input ใหญ่สุดพร้อมวัดเวลา | hint เดียวกัน, ตัวช่วยวัดขั้น | จับข้อแบบ 3781 ได้ |
| H5 | Hint หลัง `Wait` และ `Alternatively` แทนการนับ token เพดาน 3 ครั้งต่อ turn | `igc_learned_diagnostic.hpp` | เพิ่มการทดลองโดยไม่เสียข้อ |
| H6 | ตัวช่วยเทียบ brute force กับวิธีเร็วบน input สุ่ม แล้วย่อให้เหลือ input สั้นสุด | prelude | ใช้ได้บน HLE Math |
| H7 | `sys` และ stdin ในตัวแปลภาษา พร้อม `feed("...")` | `igc_sandbox.hpp` | ไม่มี block ถูกปฏิเสธเพราะ stdin |
| H8 | Fine-tune จากรอบที่แก้ตัวเองสำเร็จ | รอผู้พัฒนาตัดสิน | ทำเมื่อ H1-H7 ไม่พอ |

ลำดับทำจริง: H0 → H7 → H2 → H3 → H1 → H4 → H5 → H6 เพราะ H7 ทำให้ block รันได้ และ H2 กับ H3 ทำให้ผลมีความหมาย ก่อนจะเพิ่มจำนวนการทดลองด้วย H1 และ H5

## ตัวเลือกที่ยังไม่ทำ

- **ปิดเมื่อ `check` ตรง:** ผลตรง 15 จาก 16 ครั้งจบถูก จึงอาจประหยัด token ได้ แต่เป็นการตัดความคิด ต้องวัดหลัง H4 เท่านั้น
- **Sandbox เต็มรูปแบบ:** ทำตามแผนในเอกสารออกแบบ แยกจากแผนนี้

## เครื่องมือวัด

`tools/igc/hypothesis_read.py` อ่าน records ของแขน แล้วนับ:
- จำนวน block ที่ทดสอบกับตัวอย่าง และผลตรงหรือไม่ตรง
- ข้อที่ไม่ตรง แล้วมีการรันซ้ำจนตรง
- ผลสุดท้ายเทียบกับแขนฐาน

ตัวเลขนี้ต้องรายงานพร้อมคำตอบถูก ทุกแขน

## เงื่อนไขหยุด

- เสียข้อที่แขนฐานทำได้: อ่านข้อนั้นก่อน แล้วแก้หรือทิ้งขั้นนั้น
- ขั้นไหนไม่เพิ่มตัวชี้วัดหลัก: ไม่ใช้เป็นค่าเริ่มต้น
- H1-H7 ไม่พอ: นำข้อมูลมาให้ผู้พัฒนาตัดสิน H8

## ความเสี่ยงที่รู้อยู่แล้ว

- Hint ของ START บน LiveCodeBench เพิ่มน้อยมาก (41.4 → 42.0) ผลอาจเห็นชัดกว่าบน HLE Math
- Test ที่โมเดลเขียนเองมีจุดบอดเดียวกับโค้ด จึงใช้ตัวอย่างในโจทย์ก่อน
- ผลทั้งหมดเป็น greedy บนข้อไม่กี่ข้อ ทุกขั้นต้องยืนยันซ้ำบนข้อชุดใหม่ก่อนสรุป
