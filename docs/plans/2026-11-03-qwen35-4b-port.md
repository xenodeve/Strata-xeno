# Qwen3.5-4B on Strata's engine: the port plan (2026-11-03)

Developer's decision (2026-11-03): support Qwen3.5-4B in Strata-xeno, in parallel with the 4B arms on vLLM (#296). The developer
expected this to be easy because the whole model fits in VRAM. Placement is easy. The architecture is the work: the engine runs one
architecture, `qwen4exp` (`include/strata/artifact/gguf_reader.hpp`), which has hyper-connections (4 residual streams), a PLE n-gram
embedding, QSA sparse attention with an indexer, and MoE. Qwen3.5-4B has none of them: a plain residual, dense FFN 9216, and dense
gated attention (16 q / 4 kv heads × 256).

## The idea that keeps most of the engine unchanged: convert the 4B into qwen4exp's shape

These were read from the code, not assumed:

| qwen4exp piece | what the code computes | 4B weights that make it exact |
|---|---|---|
| HC read (`gr.hpp:81-93`, `fused_gr.cu:131-165`) | `mixed = mean_c(xn_c · sigmoid(lo @ w_up))`, with `xn_c` the per-stream RMSNorm with `w_norm` = (1+w) | `w_down = w_up = 0`, so the gate is exactly 0.5. All 4 streams stay equal, because the embedding is broadcast to every stream (`session.cpp:143`) and every write adds the same output. `w_norm = 2·(1+w)`, replicated ×4. The ×2 is exact. |
| HC write (`gr.hpp:121-124`, `fused_gr.cu:85,153`) | `R += block_out · 2·sigmoid(inject/hc)` | `w_inject = 0`, so the weight is exactly 1, a plain residual add. |
| final mixer (head) | the same read with no inject | final norm `2·(1+w)` ×4 |
| shared expert (`shared_expert.cu:5-12,78`) | `sigmoid(x·w_gate_inp_shexp) · down(silu(gate)·up)` | `w_gate_inp_shexp = 0`, so the gate is 0.5. Dense FFN as the shared expert, with `down` ×2, which scales the Q8_0 block scales exactly. |
| PLE | `--no-ple` (`verify.cpp:924`) | off |

Geometry stays `hc = 4`, `hc_lr = 320`, with only the weights zeroed, so `fused_gr`'s static_asserts hold. The cost: the zero HC projections
still read about 13 MB per mix, about 65 mixes a token, roughly 0.85 GB/token over 4.5 GB of Q8_0 weights, about +19 % decode. That is
accepted for the first port and is a measured follow-up.

## What still needs engine code (behind the new architecture only; Flash-Next stays byte-identical)

1. **Arch switch and geometry from the GGUF:** a second architecture name in the guard. `ModelGeometry` is read (32 layers, 16 q / 4 kv
   heads, GDN 16 qk / 32 v heads, n_ff 9216), and `check_all` follows it.
2. **No routed experts:** with `n_expert == 0`, the layer skips the router, the dispatch and the combine, and boot skips the expert sources,
   tiers, cache, pool and profile. This is a skip, not a new FFN.
3. **GDN output gate:** the engine has `sigmoid(z)` (`fused_gdn.cu:69`), and Qwen3.5 has `silu(z)`, which cannot be folded into a weight.
   It needs a switch in the decode and prompt GDN kernels. The prompt kernels also fix HV 48 and C 10240, which must follow the geometry.
4. **Attention:** a GQA group of 4 (the kernels fix 12, `qsa_*_attn.cu`), and dense selection with no indexer (QSA selects blocks past
   2051 cells).
5. **IGC/MIP:** the learned bundle is bound by digest to the Flash-Next files, and its taps are 4×2560 wide. The first step is a sandbox-only
   mode that runs the token-level rules (forced block, close, loop close) without the learned pipeline. A 4B bundle comes later.

## Weights

There is no native bf16/f16 GEMV (`native_mmvq.cu`: Q2_0 to Q8_0, IQ*). The 4B on Strata is **Q8_0**, while the vLLM arms are bf16.
The FT vs Base comparison stays internally consistent when both Strata arms are Q8_0. A native bf16 GEMV is a follow-up if
research-equal precision is wanted from Strata itself. The converter also has to handle:
- the V-head order: the engine pairs heads by modulo, HF by repeat_interleave;
- the norm conventions: (1+w) for the block norms, as HF stores them, and the GDN gated norm's own convention;
- the output head, duplicated from the tied embedding.

## Stages and gates

| stage | what | gate |
|---|---|---|
| 0 | Reference: teacher-forced HF logits for 5 short prompts (code, math, Thai, a long one), computed on a VM | stored logits |
| 1 | Converter (Python): HF safetensors to a qwen4exp-shaped Q8_0 GGUF and dense pack, with the weights above | one layer and the whole stack, run through the repo's reference math (`ref/gr.py` and friends) on the converted weights, match HF's hidden states |
| 2 | Engine items 1 to 4, decode first (`--short-read`) | `qual_logpos.py`: teacher-forced NLL, top-1 and KL against stage 0; and Flash-Next same-session greedy raw-token parity before/after |
| 3 | The prompt kernels follow the geometry | prompt logits match stage 0 |
| 4 | Sandbox-only IGC mode | the forced block, close and loop close fire on the 4B, read from the engine log |

The arms on Strata repeat the vLLM ones (Base, FT + MIP + Sandbox, Base + MIP + Sandbox) once stage 4 passes.

# Qwen3.5-4B บน engine ของ Strata: แผนการ port (2026-11-03)

ผู้พัฒนาตัดสินใจ (2026-11-03) ให้ Strata-xeno รองรับ Qwen3.5-4B โดยทำพร้อมกับแขนทดสอบ 4B บน vLLM (#296) ผู้พัฒนาคาดว่าไม่ยากเพราะโหลดเข้า
VRAM ได้ทั้งหมด การวางลง VRAM ง่ายจริง แต่งานอยู่ที่สถาปัตยกรรม engine รันได้สถาปัตยกรรมเดียวคือ `qwen4exp` ซึ่งมี hyper-connections
(residual 4 สาย), PLE n-gram embedding, sparse attention แบบ QSA ที่มี indexer และ MoE ส่วน 4B ไม่มีเลยสักอย่าง 4B มี residual ธรรมดา,
FFN แบบ dense ขนาด 9216 และ gated attention แบบ dense (16 q / 4 kv head × 256)

## แนวคิดที่ทำให้ engine แทบไม่ต้องเปลี่ยน: แปลง 4B ให้มีรูปร่างแบบ qwen4exp

ทั้งหมดนี้อ่านจากโค้ด ไม่ได้เดา:

| ส่วนของ qwen4exp | โค้ดคำนวณอะไร | weight ของ 4B ที่ทำให้ได้ผลตรงเป๊ะ |
|---|---|---|
| HC read (`gr.hpp:81-93`, `fused_gr.cu:131-165`) | `mixed = mean_c(xn_c · sigmoid(lo @ w_up))` โดย `xn_c` คือ RMSNorm ของแต่ละสายด้วย `w_norm` = (1+w) | `w_down = w_up = 0` gate จึงได้ 0.5 พอดี ทั้ง 4 สายเท่ากันตลอด เพราะ embedding กระจายไปทุกสาย (`session.cpp:143`) และทุกการเขียนบวกผลลัพธ์เดียวกัน `w_norm = 2·(1+w)` คัดลอก ×4 การคูณ 2 ไม่ทำให้ค่าคลาดเลย |
| HC write (`gr.hpp:121-124`, `fused_gr.cu:85,153`) | `R += block_out · 2·sigmoid(inject/hc)` | `w_inject = 0` น้ำหนักจึงได้ 1 พอดี เท่ากับบวก residual ธรรมดา |
| ตัวผสมสุดท้าย (head) | read แบบเดียวกันแต่ไม่มี inject | final norm `2·(1+w)` ×4 |
| shared expert (`shared_expert.cu:5-12,78`) | `sigmoid(x·w_gate_inp_shexp) · down(silu(gate)·up)` | `w_gate_inp_shexp = 0` gate จึงได้ 0.5 ใช้ FFN แบบ dense เป็น shared expert แล้วคูณ `down` ×2 ซึ่งคือการคูณ block scale ของ Q8_0 ด้วย 2 ได้ค่าตรงเป๊ะ |
| PLE | `--no-ple` (`verify.cpp:924`) | ปิด |

geometry คงไว้ที่ `hc = 4`, `hc_lr = 320` แค่ทำ weight ให้เป็นศูนย์ static_assert ของ `fused_gr` จึงยังผ่าน ต้นทุนคือ HC projection ที่เป็นศูนย์ยังต้องอ่านราว
13 MB ต่อการผสม ราว 65 ครั้งต่อ token รวมประมาณ 0.85 GB/token บน weight Q8_0 ขนาด 4.5 GB decode จะช้าลงราว 19 % รับได้สำหรับการ port
รอบแรก และจะวัดแล้วแก้ทีหลัง

## ส่วนที่ยังต้องเขียนโค้ดใน engine (อยู่หลังสถาปัตยกรรมใหม่เท่านั้น Flash-Next ต้องได้ผลเหมือนเดิมทุก byte)

1. **สวิตช์สถาปัตยกรรมและ geometry จาก GGUF:** เพิ่มชื่อสถาปัตยกรรมที่สองในตัวกั้น อ่าน `ModelGeometry` (32 ชั้น, 16 q / 4 kv head,
   GDN 16 qk / 32 v head, n_ff 9216) และให้ `check_all` ตรวจตามนั้น
2. **ไม่มี routed expert:** เมื่อ `n_expert == 0` ชั้นจะข้าม router, dispatch และ combine และตอน boot จะข้าม expert source, tier, cache,
   pool และ profile เป็นการข้ามเฉยๆ ไม่ใช่ FFN ใหม่
3. **output gate ของ GDN:** engine ใช้ `sigmoid(z)` (`fused_gdn.cu:69`) แต่ Qwen3.5 ใช้ `silu(z)` ซึ่งพับเข้า weight ไม่ได้ ต้องเพิ่มสวิตช์ใน kernel
   GDN ทั้งทาง decode และ prompt นอกจากนี้ kernel ของ prompt ยังกำหนด HV 48 และ C 10240 ตายตัว ต้องเปลี่ยนให้อ่านจาก geometry
4. **Attention:** GQA group 4 (kernel กำหนด 12 ไว้ตายตัว, `qsa_*_attn.cu`) และเลือกแบบ dense โดยไม่มี indexer (QSA เลือก block เมื่อเกิน
   2051 cell)
5. **IGC/MIP:** learned bundle ผูก digest กับไฟล์ของ Flash-Next และ tap กว้าง 4×2560 ขั้นแรกจึงทำโหมด sandbox อย่างเดียว ที่รันกฎระดับ token
   (บังคับเปิด block, ปิด, ปิดเมื่อวนซ้ำ) โดยไม่ใช้ learned pipeline ส่วน bundle ของ 4B ทำทีหลัง

## Weight

engine ไม่มี GEMV แบบ bf16/f16 ใน native (`native_mmvq.cu` รองรับ Q2_0 ถึง Q8_0 และ IQ*) 4B บน Strata จึงเป็น **Q8_0** ในขณะที่แขน vLLM
เป็น bf16 การเทียบ FT กับ Base ยังเท่ากันในตัวเอง เพราะแขนบน Strata เป็น Q8_0 ทั้งคู่ ถ้าต้องการความแม่นเท่างานวิจัยจาก Strata เอง ต้องทำ
GEMV แบบ bf16 ใน native เพิ่ม ตัวแปลงต้องจัดการเรื่องเหล่านี้ด้วย:
- ลำดับ V-head: engine จับคู่ head แบบ modulo ส่วน HF ใช้ repeat_interleave
- รูปแบบของ norm: block norm ใช้ (1+w) ตามที่ HF เก็บไว้ ส่วน gated norm ของ GDN ใช้รูปแบบของตัวเอง
- output head ที่ต้องคัดลอกมาจาก embedding เพราะผูกกันอยู่

## ขั้นและเกณฑ์ผ่าน

| ขั้น | ทำอะไร | เกณฑ์ผ่าน |
|---|---|---|
| 0 | ค่าอ้างอิง: logits ของ HF แบบ teacher-forced บน prompt สั้น 5 อัน (โค้ด, คณิต, ไทย, prompt ยาวหนึ่งอัน) คำนวณบน VM | เก็บ logits ไว้ |
| 1 | ตัวแปลง (Python): จาก safetensors ของ HF เป็น GGUF แบบ Q8_0 รูปร่าง qwen4exp และ pack แบบ dense ด้วย weight ตามตารางบน | รัน weight ที่แปลงแล้วผ่านคณิตอ้างอิงของ repo (`ref/gr.py` และไฟล์ที่เกี่ยวข้อง) ทั้งชั้นเดียวและทั้ง stack แล้วได้ hidden state ตรงกับ HF |
| 2 | งานใน engine ข้อ 1 ถึง 4 เริ่มจาก decode ก่อน (`--short-read`) | `qual_logpos.py`: NLL, top-1 และ KL แบบ teacher-forced เทียบกับขั้น 0 และ Flash-Next ต้องผ่าน greedy raw-token parity ใน session เดียวกัน ก่อนและหลังแก้ |
| 3 | kernel ของ prompt ให้อ่านจาก geometry | logits ของ prompt ตรงกับขั้น 0 |
| 4 | โหมด IGC แบบ sandbox อย่างเดียว | การบังคับเปิด block, การปิด และการปิดเมื่อวนซ้ำ ทำงานบน 4B ดูจาก log ของ engine |

พอขั้น 4 ผ่าน แขนบน Strata จะรันซ้ำตามแขนบน vLLM ได้แก่ Base, FT + MIP + Sandbox และ Base + MIP + Sandbox
