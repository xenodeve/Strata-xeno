# แผนการทดสอบเต็ม: MIP + Sandbox เทียบคะแนนที่เผยแพร่

ร่าง 2026-11-02 เริ่มเมื่อผลรอบนี้ (`lm1`, HLE `hon` เทียบ `htl`, คณิต `ac1`/`ac2`/`ac5`) ยืนยันว่าทาง tool ไม่เสียข้อบนชุดใหม่ ถ้าเสียข้อ ให้อ่านสาเหตุและแก้ก่อน แล้วค่อยกลับมาที่แผนนี้

## เทียบกับอะไร

| ชุด | Base (Table 11 ใน arXiv 2608.30320, Flash-Next-Base) | Model card (post-trained) |
|---|---:|---:|

| MATH | 72.78 | |

| SuperGPQA | 51.36 | |

| HLE | | 35.9 |

คะแนน Base เป็นของโมเดลก่อน post-train ส่วน Gyro-M เป็นรุ่น post-train ที่ quantize แล้ว เทียบได้ตรงกว่ากับคอลัมน์ model card ส่วนคอลัมน์ Base ใช้เพราะผู้พัฒนาขอให้เทียบ และต้องเขียนกำกับไว้ทุกครั้ง

**ตัวเลขของเราไม่ใช่ protocol ทางการ:** greedy, ตัวอย่างสุ่ม, prompt ของเรา จึงต้องรายงานทั้ง 3 คอลัมน์ คือ Gyro-M ไม่มี MIP, Gyro-M ทาง tool และคะแนนที่เผยแพร่ แล้วอ่านความต่างระหว่างสองแขนของเราเป็นหลัก

## แขน

| แขน | Flags |
|---|---|
| ไม่มี MIP | `mip: 0` (ไม่มี bundle) |
| ทาง tool | MIP + `--tool-loop --sandbox --sandbox-tool --sandbox-exec --close-repeat 0 --repeat-note 1` |

ทั้งสองแขนรันบนเครื่องเดียวกันและ engine ตัวเดียวกันเสมอ ไม่เทียบข้าม `a1` กับ `b1`

## กฎระหว่างรัน

- **ทุกแขนใช้ `--short-first` และหยุดทันทีเมื่อเสียข้อแรกที่แขนไม่มี MIP ทำได้** (`--stop-on-loss`) แล้วอ่านข้อนั้นก่อนรันต่อ
- **ชุดใดที่ผลของสองแขนต่างกันไม่ถึงขนาดที่อ่านได้ หรือ token ไม่ลด** ให้หยุดชุดนั้น เขียนผลลบไว้ แล้วไปชุดถัดไป
- **ทุกชุดที่มีคำตอบเป็นข้อความต้องผ่าน API reader** และอ่านทุกข้อที่ rule กับ reader เห็นไม่ตรงกัน
- **ข้อที่ผิด อ่านทีละข้อ** แล้วแยกสาเหตุเป็น: ความรู้, เข้าใจโจทย์ผิด, คำนวณ, ทดลองแล้วไม่เชื่อผล, ถูกตัด, ตัวตรวจผิด ใช้ผลนี้กำหนดรอบแก้ถัดไป
- **คำถามของ HLE และ GPQA ห้ามขึ้น repo, issue หรือ artifact** ให้อยู่บน VM และ scratch เท่านั้น

## สิ่งที่ต้องเตรียม

- Row builder ของ GPQA Diamond ยังไม่มี และ dataset ต้องขอสิทธิ์ใน Hugging Face ก่อน
- MATH ระดับ 5, MMLU-Pro และ SuperGPQA แยกหมวด ใช้ `tools/igc/standard_rows.py` ที่มีอยู่ เพิ่มแค่ตัวกรอง
- LiveCodeBench v6 ทุกระดับ ใช้ `std-lcb.jsonl` บน VM แล้วสุ่มด้วย seed คงที่
